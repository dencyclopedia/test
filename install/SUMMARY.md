# Tesseract install comparison (tested 2026-11-18)

All numbers come from GitHub Actions runs in this repository; nothing is estimated. The table below is generated by
[`make_summary.py`](make_summary.py) from the captured files named in its last column (paths relative to `install/`). Details and screenshots:
[`windows/README.md`](windows/README.md), [`macos/README.md`](macos/README.md), [`linux/README.md`](linux/README.md); every error message: [`ERRORS.md`](ERRORS.md).

**Machines, exactly as tested:** Windows = GitHub `windows-latest`, **Windows Server 2025 Datacenter build 26100** (not Windows 11), admin session.
macOS = `macos-latest`, **macOS 26.7.2 arm64** (Apple M1, virtual), and `macos-15-intel`, macOS 15.7.9 x86_64. Linux = clean official Docker images
on an `ubuntu-24.04` runner (root inside the container, no sudo). All machines sit in data centres with fast connections, so download-heavy steps are
quicker than on a home connection.

**Column definitions**
- *Time to working OCR*: wall time of the install steps a user must run before `tesseract image.png -` succeeds: package index refresh + install
  (+ the extra language package where the base install has none). It excludes installing the package manager itself (Scoop, MacPorts, WSL distro; given in Notes),
  Homebrew's `brew update`, and the OCR run. For the Windows GUI it is only the "Installing" page (from clicking Install until Next is enabled); clicking
  through the wizard is not counted. Single runs, not medians.
- *Download*: installer or package size as reported (installer file size; apt "Need to get"; dnf "Need to download"; pacman "Total Download Size"; zypper
  "Package download size"; conda "Total"). `n/c` = not captured (the tool did not print it).
- *Installed*: size on disk of the install folder (Windows: sum of file sizes; macOS: `du -sh` of the Cellar folder), or what the package manager says
  plus the growth of the container's root filesystem after cleaning the package cache (the latter includes repository metadata).
- *PATH set automatically?*: whether a **new** shell finds `tesseract` without any manual step (Windows: registry Path re-read in a fresh cmd process and a window opened via Explorer).

## Key findings

1. **Windows installer:** UB Mannheim's current build is **5.5.3.20260724** (26,573,224 bytes, SHA-256 `bee9e3434bd94fd65387d9be28cd467a41f61b1275383b55b0f59a1331270ae4`). It is linked from the UB Mannheim wiki but hosted as an asset of the **upstream `tesseract-ocr/tesseract` 5.5.3 release**, not on UB-Mannheim's own GitHub releases page (whose "latest" is still 5.4.0.20240606) and not on digi.bib.uni-mannheim.de (newest there: 5.4.0.20240606). The `v5.5.3.20260724` tag in UB-Mannheim/tesseract has no release and no assets. Tesseract 5.5.4 (2026-10-28) has no Windows installer yet.
2. **Only Chocolatey and Scoop set PATH on Windows.** The UB Mannheim installer (GUI) and both winget ids leave PATH alone, and a new cmd window says `'tesseract' is not recognized…`.
3. **winget `UB-Mannheim.TesseractOCR` still installs 5.4.0.20240606**; `winget install tesseract-ocr.tesseract` gives 5.5.3.
4. **Some "successful" installs cannot OCR anything** because they ship no language: Alpine `tesseract-ocr`, Scoop `tesseract`, MacPorts `tesseract`. The error is `Error opening data file …/eng.traineddata`.
5. **Distro versions differ a lot:** Ubuntu 22.04 = 4.1.1, Ubuntu 24.04 = 5.3.4, Debian 12 = 5.3.0, Debian 13 = 5.5.0, Alpine = 5.5.2, Fedora 45 / Arch / openSUSE Tumbleweed / conda-forge / Homebrew (arm64) = 5.5.4, MacPorts = 5.5.3, PPA alex-p for Ubuntu 24.04 = 5.5.1.
6. **All languages:** Windows installer with everything ticked = 800.9 MB on disk (124 traineddata); `brew install tesseract-lang` = 654M, 162 languages; `scoop install tesseract-languages` = 700.4 MB, 162 languages; apt `tesseract-ocr-all` = 686 MB (160 packages). conda-forge's `tesseract` already includes 125 languages.
7. **WSL2 works on the GitHub Windows runner:** Ubuntu 24.04 in WSL gave Tesseract 5.3.4 after a 5.9 s `apt-get install`.
8. **Intel Mac:** on `macos-15-intel`, Homebrew compiled the dependency chain from source; see `macos/README.md`.

## What could not be done

- **Windows 10/11 desktop editions**: GitHub only offers Windows Server runners. Nothing here is labelled Windows 11.
- **Non-admin Windows installs**: every runner session is an administrator, so "no admin needed" (Scoop) could not be proven, only that Scoop installs into the user profile.
- **SmartScreen / Mark-of-the-Web**: the installer was fetched with `Invoke-WebRequest`, not a browser.
- **`macos-13` (Intel, macOS 13)**: jobs never got a runner (stayed queued); Intel results are from `macos-15-intel` instead.
- **Chocolatey, Scoop and Homebrew download sizes** were not printed by the tools, so they are `n/c`.
- **MacPorts in Terminal.app**: MacPorts was captured as a script log only (no screenshots).
- **`pip install` of Tesseract itself**: there is no official pip package that ships the Tesseract binary; `pytesseract` only calls an installed binary (shown failing without it in `ERRORS.md`). Not tested further.
