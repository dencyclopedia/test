Browser vs native Tesseract on the same images

The browser engine is an older Tesseract build (5.1.0 development snapshot, best_int models) than the current native release (5.5.4). On these 16 images that mattered less than the tool's own steps.

  • 0.00%clean page, two-column page: same CER as native 5.5.4
  • 0.00%sideways page in the tool vs 84.93% native PSM 3
  • 5.08%Chinese in the tool vs 88.81% native (spaces)
  • 26.56%receipt phone photo vs 20.09% native
Source: bench/ocr-online/results-2026-11-18-rtl-fix (comparison.csv) · native: tesseract 5.5.4 --oem 1 --psm 3, tessdata · 2026-11-18
  • Clean pages match. The 300 DPI page, the two-column page and the Russian page came out at exactly the same CER as native 5.5.4 (0.00%, 0.00%, 0.35%); the 150 DPI page at 0.18% in both.
  • Sideways and upside-down pages: the tool wins. When the first pass scores below 50% confidence, the tool tries the other three orientations on a smaller copy and keeps a clearly better one. Both rotated pages came out at 0.00% CER. Plain tesseract --psm 3 does not turn pages and returned 84.93% and 84.42% CER; native Tesseract needs orientation detection (--psm 1) for that.
  • Chinese: the tool wins on spacing. Native Tesseract put a space between almost every character (88.81% CER). The tool sets preserve_interword_spaces=1, which removes them: 5.08%.
  • Receipt photos: native is better. The simulated phone photo of a receipt was the hardest image for both, 26.56% in the tool and 20.09% natively. For crumpled or shaded receipts, try Layout mode PSM 6 and Enhance contrast, or crop to the text.

Arabic: a bug in this tool, found and fixed

Our first run of the tool on an Arabic page returned 16.00% CER against 2.12% for native Tesseract, with one whole line missing and words glued together (لحقوقالإنسان, فيالعالم). It was the tool's fault, not tesseract.js:

  • Glued words: preserve_interword_spaces=1, which the tool sets to fix Chinese and Japanese spacing, drops the spaces between Arabic words. Native Tesseract 5.5.4 does the same with that setting. The tool now turns it off when the document or second language is written right to left (Arabic, Persian, Urdu, Hebrew and other RTL codes).
  • Missing line: the tool drops lines below 30% confidence as noise. Tesseract scored the missing line 27% because its first word scored 27%; the other 15 words scored 89–93%. The tool now judges a line by the mean confidence of its words.

With both changes the same Arabic page scores 1.25% CER (word recall 67.4% → 94.1%), now slightly better than native 5.5.4 with the standard model (2.12%) and the best model (1.38%). The other 15 images gave exactly the same text before and after the fix. We tested one Arabic page; Persian, Urdu and Hebrew get the same fix but we have not measured them.

Why choose Tesseract Online OCR?

It is the open-source Tesseract engine with no account, no upload and no watermark, and with the extra steps a browser tool needs to cope with photos and screenshots. What it does, as the code and our tests show:

  • Private: recognition runs in a Web Worker in your tab; we captured every network request during a run (below) and none carried the image.
  • 43 languages in the menu, and a second language for mixed documents (for example deu + eng).
  • Preprocessing that runs before Tesseract: images narrower than 1,200 px are upscaled, uneven lighting is flattened, light-on-dark screenshots are inverted, and dark panels in a light screenshot get a second, inverted pass.
  • Automatic orientation retry for sideways and upside-down pages (0.00% CER on both test pages).
  • Exports: copy, a .txt file, or a searchable PDF made by Tesseract's own PDF renderer (image plus an invisible text layer).
  • SIMD WebAssembly: in our Chromium runs tesseract.js loaded its SIMD build (tesseract-core-simd-lstm). It uses one worker, so pages are recognised one after another, not in parallel.

How to extract text from images

Video: get clean text from any image

A 3-minute walkthrough of this tool, including the layout mode setting that fixes most messy results.

Step by step

  1. Add the file. Drag and drop an image or PDF onto the box, click Browse files, or paste a screenshot with Ctrl+V / ⌘+V.
  2. Pick the language of the document. Add a second language if the text mixes two (each one is a separate model download the first time).
  3. Choose a layout mode if the default fails: Automatic page layout (PSM 3) for pages, Single block / receipt (PSM 6) for receipts and forms, Single line (PSM 7) for one cropped line, Sparse text (PSM 11) for signs, banners and graphics.
  4. Click Extract text. On desktop the word boxes appear over your image, coloured by confidence: 90–100%, 60–89% and below 60%. Red boxes are the words to check.
  5. Use the result: edit it in the box, then Copy, Download TXT or Searchable PDF. Clean text removes lines that hold only symbols or stray letters.

Frequently asked questions

Is the online OCR free?

Yes. The tool is free, needs no sign-up and adds no watermark. Its limits are technical: a file can be up to 20 MB, and from a PDF the first 20 pages are recognised.

Are my images uploaded to a server?

No. OCR runs in your browser with tesseract.js, Tesseract compiled to WebAssembly. Only the engine and the language model are downloaded, from cdn.jsdelivr.net. We recorded every network request during a run with Playwright: all were downloads and none carried the image.

Which file formats are supported?

PNG, JPG/JPEG, WEBP, BMP and GIF images, plus PDF files of up to 20 pages — each page is rendered and recognized in your browser. You can download the result as plain text or as a searchable PDF. For larger batches, use the command-line or Python workflow in the PDF guide.

Which languages can it recognize?

43 languages in 13 writing systems, including English, Spanish, Portuguese, German, French, Italian, Japanese, Chinese, Turkish, Indonesian, Russian, Arabic, Hindi and Korean. You can pick a second language for documents that mix two. The full list is in the language table on this page.

Is there a page or file size limit?

Yes: 20 MB per file and 20 pages per PDF. A longer PDF is not rejected; the tool reads the first 20 pages and tells you how many it skipped. Very large images are scaled down to 16 megapixels before recognition. For long documents, use OCRmyPDF or the Tesseract command line on your computer.

Does it work offline or on a phone?

After the first run, yes for the same language: in our test we switched the browser offline and the tool still read a second page, because the engine and the model were already loaded. The first use of each language needs a connection to download the model. On phones the page uses a one-column layout and scales images above 16 megapixels down; we have tested it in Chromium at a phone-sized screen, not on physical phones.

Why is my output garbled or in the wrong order?

Check the language first: the wrong model produces nonsense. Then try another Layout mode: Single block (PSM 6) for receipts, Sparse text (PSM 11) for signs and graphics. Tick Enhance contrast for faded or grey scans, and crop photos to the text. In our tests a phone photo of a receipt had 26.56% character errors, and a dashboard screenshot was read column by column (all words found, in a different order). A high confidence badge does not prove the text is correct.

How accurate is it compared with desktop Tesseract?

On clean pages it gave the same result as native Tesseract 5.5.4 in our 16-image test (0.00% character errors on a 300 DPI page). It was better on sideways and upside-down pages (0.00% vs 84.93% and 84.42%) and on Chinese spacing, and worse on a receipt photo (26.56% vs 20.09%). The browser engine is tesseract.js 5.1.1, built from a Tesseract 5.1.0 development snapshot.
